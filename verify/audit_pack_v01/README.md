# Move 85 — Rust audit pack v1

## What this is

The closure and independent-verification handoff for the Moves 71–85
Rust-hardening block, and the audit pack the roadmap asks for: clean,
tampered and corrupted bundles with the Python lane's outputs, the Rust
lane's outputs, instructions and known limits.

## The pack is generated, not shipped

`build_audit_pack.py` is source. **The pack is not.** It is produced by
the adoption gate from freshly built binaries and published into
`MOVE85_OUTPUT_DIR/audit_pack_v1/`. A pack committed as source would be a
claim; a pack generated by a gate run is a measurement.

Nothing is published until every substantive check has passed: candidate
identity and source binding, inherited immutability, clean builds and
tests, controlled behaviour, pack generation, representation determinism,
the focused suite, the complete adopted Move 84 regression, and package
hygiene. Two representations are generated in private staging; the
**already-verified first** one is published, and the second exists solely
for the determinism comparison and is never published. Nothing is
regenerated during publication — regenerating would publish an artifact no
check had passed.

After copying, the gate independently verifies the published tree against
the staged source (every path, type, mode and byte) and recomputes
`SHA256SUMS` from the **published** bytes. A partial or failed publication
is rolled back, and the terminal
`MOVE_85_AUDIT_PACK_ADOPTION_GATE: PASS` marker is unreachable unless the
published pack exists and has been verified after publication.

The standalone `witness-verify` binary and its build-provenance record
also remain in the output directory. They are **supporting measurement
machinery** — how the pack's measurements were taken. **The audit pack is
the Move 85 roadmap deliverable; the binary is not.**

## Published structure

```
audit_pack_v1/
    MANIFEST.json            index, hashes, per-case measurements
    INSTRUCTIONS.md          how to reproduce every measurement
    KNOWN_LIMITS.md          what the pack does and does not establish
    SHA256SUMS               one line per published file
    bundles/<case_id>/       the exact tree each case was measured over
    observed/<case_id>/rust.stdout    captured bytes, verbatim
    observed/<case_id>/rust.meta      exit code and stderr byte count
    observed/<case_id>/python.stdout
    observed/<case_id>/python.meta
```

Everything under `observed/` is an **authoritative measurement** — the
exact bytes a real execution produced. `INSTRUCTIONS.md` and
`KNOWN_LIMITS.md` are **explanatory text**, and `MANIFEST.json` labels
which is which.

## adopted_facts.json is a claim manifest, never an authority

Every entry names the external authority that establishes it and the
method by which the gate checks it. The gate compares the manifest
**against** those authorities — externally supplied adopted artifacts with
externally pinned hashes, adopted gate and source bytes, or fresh
execution. It never compares an authority against the manifest, and no
value is established because this file contains it.

## Determinism boundary

`MANIFEST.json`, `INSTRUCTIONS.md` and `KNOWN_LIMITS.md` regenerate
byte-for-byte from the same inputs. The manifest therefore carries no
timestamp, no temporary absolute path, no random name, no run-directory
identity and no host-specific value; paths are relative to the pack root
and lists are explicitly sorted.

**This is a determinism claim about the pack representation only. It is
not a claim that Rust binaries or builds are reproducible.** Nothing in
this move measures that.

## Two separate no-PASS claims, deliberately not merged

- **Source-level contract:** the adopted Rust source declares exactly two
  verdict constants, `VERDICT_FAIL` and `VERDICT_INCONCLUSIVE`. No PASS
  verdict constant exists. This is machine-checked from adopted bytes.
- **Empirical:** no Rust PASS was observed across the measured surfaces.

Neither claims that no reachable PASS-producing path exists anywhere in
the program. Finite execution cannot establish global reachability, and no
such proof is offered.

## Known limits carried forward

The Rust verifier does not detect a tamper to the nested evidence payload;
its output there is byte-identical to the clean case. The gate **fails if
that blindness is not observed**, so the limitation cannot quietly vanish.
The two adopted divergence IDs are read from the adopted Move 79 gate at
run time, never from a list written here. Only Android/Termux AArch64 has
been build- and runtime-tested.
